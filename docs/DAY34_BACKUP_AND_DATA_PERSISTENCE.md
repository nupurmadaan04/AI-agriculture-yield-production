# DAY 34 — Backup & Data Persistence Classification

## Data Asset Classification

### Critical — Must Never Be Lost

| Asset | Path | Description | Recovery Difficulty |
|-------|------|-------------|---------------------|
| Canonical dataset | `Datasets/final_agricultural_data_cleaned.csv` | 71,601 cleaned records | Very High (manual reconstruction from ICRISAT/state sources) |
| Raw uploads | `Datasets/uploads/` | Original source CSV files | High (requires re-download from data providers) |
| Serialized models | `Models/multicrop/*.pkl` | Trained scikit-learn artifacts | Medium (can regenerate via training scripts, takes ~30min) |
| Strategy registry | `Models/multicrop/forecast_strategy_registry.json` | Certification decisions per crop | Medium (regenerated by training pipeline) |
| Coverage map | `Datasets/metadata/forecast_coverage.csv` | District/crop coverage index | Low (regenerated from dataset) |

### Operational — Important But Regenerable

| Asset | Path | Description | Recovery Difficulty |
|-------|------|-------------|---------------------|
| Prediction audit log | `Datasets/metadata/prediction_audit_log.csv` | Historical prediction log | Low (starts fresh; historical data lost) |
| Operational telemetry | `Datasets/metadata/operational_telemetry.jsonl` | Runtime metrics JSONL | None (rolling window only) |

### Ephemeral — No Persistence Required

| Asset | Path | Description |
|-------|------|-------------|
| uvicorn logs | stdout | Ephemeral; redirect to centralized log service |
| React dev server cache | `frontend/.vite/` | Rebuild at startup |
| pip cache | `/root/.cache/pip/` | Re-downloaded on rebuild |

## Backup Procedures

### Critical Data (Manual Backup Protocol)

```bash
# 1. Backup canonical dataset and models
cp -r Datasets/ /backup/agri-$(date +%Y%m%d)/Datasets/
cp -r Models/ /backup/agri-$(date +%Y%m%d)/Models/

# 2. Verify backup integrity
md5sum Datasets/final_agricultural_data_cleaned.csv
md5sum Models/multicrop/*.pkl
```

Recommended: Nightly snapshot of `Datasets/` and `Models/` directories.

### Operational Logs

```bash
# Archive monthly prediction audit log
cp Datasets/metadata/prediction_audit_log.csv \
   /archive/audit_logs/audit_$(date +%Y%m).csv
```

## Docker Volume Persistence

When running via Docker Compose, volumes are host-mounted (not Docker-managed named volumes):

```yaml
volumes:
  - ./Datasets:/app/Datasets       # ← Data survives container restart
  - ./Models:/app/Models           # ← Models survive container restart
```

**Implication**: Data is NOT isolated in Docker volume storage — it lives in the host filesystem alongside the repository. This is intentional for a research deployment model.

## Storage Limitations

| Limitation | Notes |
|-----------|-------|
| No automated cloud backup | Containerized; backup is manual host-level operation |
| No versioned model registry | pkl files overwritten on retrain |
| Audit log not deduplicated | Append-only; may grow unbounded in long-running deployments |
| Telemetry not rotated | `operational_telemetry.jsonl` should be rotated monthly |
